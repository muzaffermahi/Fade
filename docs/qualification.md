# Candidate qualification protocol

Keep the archive prerelease until every release-checklist gate has actual evidence. Record the archive SHA-256 with each result. Do not infer macOS/Linux or physical terminal/IME behavior from Windows or an in-memory render sink.

For each OS: clean Node/Bash install, isolated local archive installation, native login/model configuration using synthetic credentials/account, help, startup, an exploratory message with no edits, supported implementation with real check, conversation during the edit, /builder and /changes inspection, conflict resolution, pause/redirect, crash/restart paused, explicit continuation, upgrade and uninstall. Capture 80×24, 120×40, resize, long paste/CJK/IME, light/dark theme, scroll/focus restoration and tool streaming. Record hardware plus startup/input/activity timing. Separate provider latency.

Use explicitly selected role models for opt-in live scripts. The current human selection is OpenCode Go's free models, with a cached local model as a fallback. Historical GLM results below belong to earlier artifacts and do not select a paid model for current qualification. Preserve failures, not just successful reruns. A rejection for unsupported human evidence is a safety hold, not a passed workflow.

Recruit five developers unfamiliar with Fade. Each independently installs, starts useful work, continues thinking during implementation, inspects the outcome, redirects and resumes after interruption. Do not coach. Record anonymized IDs, OS, candidate hash, completion yes/no, coaching yes/no, task time, errors, data loss/unintended execution, and observations. At least four must complete without coaching; any data loss/unintended execution blocks release.

No participant results or clean macOS/Linux runs have been recorded here. A prepared workflow or smoke script does not satisfy those gates. Publication needs separate human authorization.
