# Fade 1.0 product contract

Human-selected direction, updated 2026-10-11: develop software's future with the Companion while the Builder implements its settled present. Terminal-first on Windows, macOS and Linux. Builder, Companion and Fade modes; independent role histories, drafts, scroll positions and routed receipts; Fade opens a persistent split workspace during implementation. Fade is a mode, not a third agent. The attached selected image defines mint/lavender/ivory on charcoal styling and the dissolving character wordmark.

## Authority and compatibility

Fade is independent of parent Veto. This contract supersedes Fade's earlier automatic starter slice and prompt-only concurrent edit avoidance. Preserve parent files and unrelated experiments. Implementation authorizes no Git commit, push, package publication or public release.

Keep two Pi roles and a coordinator. Preserve Pi's editor, steering/follow-up distinction, themes, remappable controls, authentication, model selection, resources and session features. Builder retains stock implementation tools. Companion has no project write/shell/generated-code/delegation authority, even while Builder is idle or a human shell is running. Only known read-only capabilities and validated coordinator metadata interfaces are exposed and dispatched. Unknown extension/MCP tools are excluded regardless of annotations. Native Pi controls remain available through a public renderer handoff; no private transcript containers or patched dependencies. One terminal renderer owns the screen. This boundary is not an OS sandbox against external programs or user-installed extension code.

## Requirements

- F-INTENT: message arrival never starts a slice. A concrete human implementation request supports an evidence-backed bounded brief with nonempty settled references, requirements and acceptance checks. Exploration, quoted suggestions and conflicts do not authorize execution. One immutable active brief and one revisable future slot; discoveries and relevant intent changes hold future work for reconciliation. Intent edits have human-message provenance.
- F-INPUT: accepted input is durable before acknowledgement. Receipts identify session, role, steering/follow-up mode, attachments and processing status. Queue editing/cancellation preserves history. Session navigation never reroutes accepted input. Recovery is paused; uncertain operations are shown and never automatically replayed.
- F-OWNERSHIP: Builder owns implementation mutations; Companion stays read-only. Human native shell runs only after Builder quiescence. Inspection continues concurrently. Explicit redirection retains the old slice history.
- F-EVIDENCE: typed sequenced work events carry slice, phase, tool lifecycle, outcome and timestamps. Observed tool/command results are separate from model verification claims. Failed necessary checks cannot become verified completion. External edits are preserved; uncertain diff attribution is stated.
- F-TUI: compact Fade/workspace/models/readiness startup, actionable failures immediately, routine inventories/updates in diagnostics. Now shows task, honest phase and elapsed time; Next shows upcoming slice or waiting reason; Needs you appears only when relevant. At 80×24 the strip is at most four rows. Updates preserve focus and reading position. One compact outcome card, incorporated into Companion context at a safe boundary.
- F-VIEWS: native overlays for builder, intent, changes, searchable paginated logs, status and help. Intent can be edited/resolved without JSON. Inspection does not append model context or conversation. Retain command aliases.
- F-CONTROL: only the focused composer accepts typing; its role/session is captured on acceptance. Escape closes overlay first, otherwise interrupts the focused role. `/pause` retains partial Builder work; `/stop` disables automatic continuation. `/redirect` interrupts and develops replacement intent. Mode/focus changes never cancel execution. At narrow widths, show the focused conversation plus shared Builder status.
- F-SHARED: refresh source-labelled shared context at provider boundaries, without replacing role instructions or treating discussion/model suggestions as authority. Builder can resolve an explicit request to build the one clear discussed plan; incompatible plans and unresolved decisions require clarification. Active briefs stay immutable. Companion observes actual work and evidence; Builder sees relevant human planning, settled decisions and tentative suggestions.
- F-CONTINUITY: validated versioned schemas, shared command layer for interactive/plain modes, v1 backup migration preserving all provenance, journal checkpointing without deletion of history, bounded log/render loading. Default run limit four, configurable and visible. Unknown cost displays as unknown.
- F-RELEASE: fault tests, real terminal captures and packaged smoke checks on all three OSes. Strict TypeScript, deterministic tests, production build. Real-provider runs use explicitly selected models. MIT distribution with attribution, contributor/security docs, examples, changelog, CI, troubleshooting and install/upgrade/uninstall instructions.
