# Fade v0.4 polish and capability verification

Implemented on `codex/claude-review`. No commits or pushes. One new runtime dependency:
`pi-web-access@0.41.0`, pinned in package.json and the lockfile.
All edits are inside the nested Fade repository. The parent Veto status table is unchanged;
Fade has no IMPLEMENTATION_STATUS.md row to mark passed.

## Behavior

One Fade conversation and composer; optimistic queueing and read-back; title-based work tools;
ambiguous messages go to the Companion; exact stop, undo/undo that, yes/y/go/ok fast paths.
Corrections replace the body, stop active work and reference the exact checkpoint for start-over.
Conditional Now / Next / Needs you rail, compact active status at narrow widths and a one-line header.
Idle conversations use the full width; empty sections disappear and paths wrap with hanging indentation.
Deterministic outcome messages, archived proof output for Show, four primary keys,
six commands and Pi skill/template pass-through. Removed visible goals, progress dots and goal-done
messages. Internal card events and repeated bodies stay out of the conversation. Removed dual input, attention ranking, runway,
plan/review action keys, recap/closure/edit dialogs and Pi handoff screens.
Proof reruns, verdicts, single retry, quiet landing and intelligent undo remain.

Double Ctrl+C clears input and warns before quitting, including overlays and startup.
After a minute of quiet the empty idle composer changes its placeholder; no message/model turn is added.
Prompts describe general behavior rather than the test script or an obsolete pane arrangement.

Source: **3799 lines**, below 3,800. Demo undo restores actual demo artifacts.
Checkpoint failures stay in Needs you and explain why no checkpoint was saved.

`fade_check` checks Python syntax and existing unittest/pytest tests, JavaScript syntax and local
TypeScript types. Missing dependencies and empty test discovery do not count as runtime verification;
proof commands preserve filenames as data and can be independently rerun.
Web search/fetch is available in both sessions. Builder sessions explicitly load native MCP discovery
and codemode; the conversation session excludes arbitrary MCP, shell and edit tools.
See rebuild-plan.md for the article/package decisions and source links.

## Final acceptance pass

An actual Windows PTY demo completed the request, offered choice, build, look acceptance,
undo and next-proposal flow using text and Enter. Undo removed the corresponding artifact.
A fresh real CLI PTY verified the version change, retained real checks in Show, and reverted
the exact change. This exposed two conversation issues: inspection offered acceptance again,
and an unspecified subjective direction was queued without a choice. A subsequent real-model
run offered the choice but omitted human judgment from its criteria and quietly landed the copy.
The general Companion
instructions now keep inspection concise, reserve acceptance for waiting results, and ask for
a direction and human judgment for subjective work. The conversation smoke now fails immediately
if a subjective result skips its look. Unchecked-result copy also avoids doubled periods.

One later PTY checkpoint encountered a transient Git index lock. Fade retained it in Needs you
and explicitly reported that no checkpoint was saved; it did not quietly accept the result.

`node --import tsx scripts/conversation-smoke.ts opencode-go/kimi-k3` then **passed** in one
uninterrupted fresh session: version, independently executed proof, checkpoint undo, a subjective
direction question, ordinal selection without another confirmation, a human look question, and
“yes” acceptance. Evidence: `output/v0.4-conversation-kimi.txt`; temporary repository
`C:\Users\LENOVO\AppData\Local\Temp\fade-v04-live-wlAutz`.
Reopening that repository in the built CLI and asking “show me the result” restored the archived
checks in Show after restart; waiting reviews stayed at zero. The model's follow-up was still wordier
than desired and suggested keeping/tweaking already accepted work, so concise inspection language
remains model-dependent even though it did not change acceptance state.

The Flash runs are retained as failures, not counted as passes:
`output/v0.4-conversation-final.txt`, `output/v0.4-conversation-acceptance.txt`, and
`output/v0.4-conversation-complete.txt`. They exposed omitted subjective looks, then an unnecessary
objective look and invented unknown-flag behavior. Prompt and tool-description corrections improve
guidance but do not guarantee model compliance. The final comparison passed with Kimi; saved model
preferences were not changed. No implementation checks remain unfinished; model reliability and the
first-time-human study remain explicit validation limits.
